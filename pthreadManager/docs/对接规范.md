## 1. 任务函数签名

所有提交到线程池的任务函数必须符合 **pthread 标准回调格式**：

```c
void* task_function(void* arg);
```

- 参数 `arg`：接收一个 `void*` 指针，指向调用方传入的参数
- 返回值 `void*`：当前版本不收集返回值，可返回 `NULL`

## 2. 参数管理规范

### 2.1 参数结构体

你需要自行定义参数结构体，例如：

```c
typedef struct {
    int id;
    double value;
    // ... 其他字段
} my_task_param_t;
```

### 2.2 内存所有权规则

| 阶段 | 责任方 | 说明 |
|------|--------|------|
| 分配 | 调用方 | `malloc(sizeof(my_task_param_t))` |
| 所有权 | 调用方 | `submit` 后池内不可见参数生命周期 |
| 释放 | **回调函数内** | 任务函数返回 **前** 必须 `free(arg)` |

**规则**：线程池仅管理内部的 `task_node`（链表节点）。`arg` 指针按值传递，池不干涉其生命周期。

**严禁**：
- 在 `submit` 后、回调执行前释放或复用参数
- 在回调中释放后继续访问参数
- 传递栈上局部变量地址（生命周期短于线程执行时间）

### 2.3 推荐写法

```c
// 在回调函数末尾释放参数
void* my_task(void* arg) {
    my_task_param_t* p = (my_task_param_t*)arg;
    // ... 使用 p->id, p->value 执行任务 ...
    free(p);
    return NULL;
}
```

## 3. 生命周期与线程包装器

### 3.1 包装器机制

线程池内部为每个工作线程运行一个 **包装器**，无需用户感知：

```
worker_wrapper:
  loop:
    queue_pop(阻塞等待)     ← 无任务时休眠，不占 CPU
    ↓ 有任务
    task->func(task->arg)  ← 调用用户的任务函数
    ↓ 返回
    内部收尾(active--, 信号通知)
    goto loop              ← 立刻取下一个任务
```

### 3.2 线程生命周期

```
thread_pool_create(0)
  │
  ├─ 检测 CPU 核心数 → 最优线程数 N
  └─ 启动 N 个工作线程 → 全部阻塞在 queue_pop，等待任务
        │
        ├─ submit → 入队 → 唤醒一个线程 → 执行 → 再取下一个
        ├─ submit → 入队 → 唤醒一个线程 → 执行 → 再取下一个
        └─ ...
        │
thread_pool_wait_all()     ← 阻塞直到所有任务完成
thread_pool_destroy()      ← 通知线程退出 → join → 回收资源
```

**关键**：池中始终保持恰好 N 个活跃线程并发处理任务，完成一个立即取出下一个，永不轮询。

## 4. 提交与同步

### 4.1 提交任务

```c
my_task_param_t* p = malloc(sizeof(my_task_param_t));
p->id = i;
p->value = i * 1.5;

thread_pool_submit(pool, my_task, p);
```

`submit` 是非阻塞的：将任务入队后立即返回，工作线程异步执行。

### 4.2 等待完成

```c
thread_pool_wait_all(pool);
```

阻塞直到 **所有已提交任务全部执行完毕**（队列为空且活跃计数为 0）。适用于：

- 提交一批任务后等待完成
- `destroy` 前确保无残存任务

### 4.3 状态查询（非阻塞）

```c
int pending = thread_pool_queue_size(pool);    // 待处理任务数
int active  = thread_pool_active_count(pool);  // 正在执行的任务数
```

## 5. CPU 利用率配置

默认情况下，公式按纯计算负载（CPU 利用率 100%）计算最优线程数：

```
N = core_count × (1 + (1 - ratio) / ratio)
```

| CPU 利用率 ratio | 公式结果 | 适用场景 |
|---|---|---|
| `1.0`（默认） | N = core_count | 纯计算，无等待 |
| `0.5` | N = core_count × 2 | 一半计算一半等待 |
| `0.25` | N = core_count × 4 | 轻度计算，大量等待 |

**配置方法**（在 `create` 前调用）：

```c
thread_pool_set_cpu_ratio(0.5);          // 调整为混合负载
thread_pool_t* pool = thread_pool_create(0);  // 按新ratio计算
```

也支持手动指定线程数：

```c
thread_pool_t* pool = thread_pool_create(8);  // 直接指定 8 个线程
```

## 6. 完整对接示例

```c
#include "thread_manager.h"
#include <stdio.h>
#include <stdlib.h>

// ── [1] 定义参数结构体 ──
typedef struct {
    int id;
    double value;
} task_param_t;

// ── [2] 实现任务函数 ──
void* my_task(void* arg) {
    task_param_t* p = (task_param_t*)arg;

    // 执行实际工作
    double result = 0.0;
    for (int j = 0; j < 1000000; j++)
        result += j * p->value;

    printf("[%04d] done, result=%.2f\n", p->id, result);

    free(p);       // ← 必须释放参数
    return NULL;
}

int main() {
    // ── [3] 创建线程池（自动最优线程数） ──
    thread_pool_t* pool = thread_pool_create(0);

    // ── [4] 批量提交 ──
    for (int i = 0; i < 500; i++) {
        task_param_t* p = malloc(sizeof(task_param_t));
        p->id = i;
        p->value = i * 0.5;
        thread_pool_submit(pool, my_task, p);
    }

    // ── [5] 等待全部完成 ──
    thread_pool_wait_all(pool);

    // ── [6] 销毁 ──
    thread_pool_destroy(pool);
    return 0;
}
```

## 7. 注意事项

### 7.1 线程安全
- 线程池内部已做完整同步，所有公有 API 都是线程安全的
- 你的任务函数应避免访问未保护的全局/静态变量
- 若任务间需共享数据，请自行加锁（如 `pthread_mutex_t`）

### 7.2 参数内存
- 调用 `submit` 后，不要再读取或修改参数指针指向的内容
- 任务函数必须 `free(arg)`，否则会导致内存泄漏
- 如需在任务间共享数据，传递共享结构体指针而非各拷贝一份

### 7.3 错误处理
- `submit` 返回 `-1` 表示失败（参数为空或 `malloc` 失败）
- `create` 返回 `NULL` 表示创建失败（资源不足）
- 内存分配失败的恢复策略由调用方自行决定

### 7.4 销毁顺序
```
1. 停止 submit（不再提交新任务）
2. 调用 thread_pool_wait_all（可选，destroy 内部也会调用）
3. 调用 thread_pool_destroy
```
