# 4\.4\.2 死代码消除（Dead Code Elimination）

**死代码**是指：计算结果**从未被任何有用语句使用**的代码。

### 基本定义

粗略来说，**有用语句**包括：

- 输出语句（直接对外界产生可见效果）；

- 为输出语句提供数据的语句；

- 为有用语句提供数据的语句。

死代码消除算法的核心思路：**找出所有有用语句，删除其余所有语句**。

### 死代码消除算法（伪代码）

```Plain Text
procedure eliminateDeadCode(P)
// P：待优化过程；假设所有语句均已构建 定义-使用链（def-use chains）

// 1. 初始化：绝对有用语句集合
worklist := { 输出语句、控制流语句、输入语句 }

// 2. 反向遍历：收集所有有用语句
while worklist ≠ ∅ do
    x := 从 worklist 中任取一个语句
    标记 x 为“有用”
    worklist := worklist – {x}

    // 遍历所有“y → x”的定义-使用边（y是x的前驱定义）
    for all (y, x) ∈ def-use do
        if y 未标记为有用 then
            worklist := worklist ∪ {y}

// 3. 删除未标记语句
删除所有未被标记为“有用”的语句

end eliminateDeadCode
```

### 典型效果

该算法常被用来暴露**基准测试程序**中的问题：

- 开发者关注**运行时间**，而非计算结果；

- 部分基准仅输出时间、不输出结果；

- 编译器执行死代码消除后：**整个计算逻辑被删除**，仅保留 “读取时钟→计算差值→打印时间”，运行速度极快。

### 控制流相关问题

上述简单算法对**控制流条件表达式**处理不足：

- 条件表达式不直接产生 “被使用的值”，但**决定后续语句是否执行**；

- 简单方案：将所有条件语句直接标记为 “绝对有用”，若其控制的语句全部被删除，再删除条件语句；

- 高级方案：在定义 \- 使用链中加入**控制依赖边**（第 7 章详述），可获得更精准结果。
