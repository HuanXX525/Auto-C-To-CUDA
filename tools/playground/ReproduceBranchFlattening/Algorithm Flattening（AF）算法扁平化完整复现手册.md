## 1 基础背景与核心目标

### 1\.1 问题根源

GPU SIMD 架构存在**线程分叉 Thread Divergence**：分支（if/else/ 嵌套 if/else if/switch）使同一 warp 内线程执行不同路径，硬件串行执行所有分支，计算单元闲置，性能暴跌。
现有优化（分支合并、代码复制、谓词执行）仅减少分支，**无法彻底消除控制流分支**；性能随输入波动、不可预测。

### 1\.2 AF 核心思想

放弃 CPU 友好的控制流写法，将**所有条件分支控制流等价转换为纯算术表达式**，彻底移除 if、else、else if、嵌套条件等分支语句；

- 代价：CPU 上指令量上升，运行变慢（劣化 de\-optimization）

- 收益：GPU 无线程分叉，ALU 指令级并行 ILP 拉满，硬件利用率大幅提升，性能确定可预测。

### 1\.3 适用 / 不适用范围

#### 支持处理

1. 单层`if`、`if-else`

2. 多层嵌套 if\-else

3. 连续 else if 分支链

4. 分支内多步算术计算、临时变量、多变量赋值

5. 布尔判断、数值比较条件（`==` `!=` `<` `>`等）

6. 多变量同时更新

#### 不支持处理

1. 循环语句（for/while）

2. 外部函数调用、内存读写、IO 操作

3. 无法用算术表达的硬件原语

## 2 AF 完整转换理论（可直接编码实现）

### 2\.1 布尔值算术映射规则（底层基础）

所有条件表达式映射为**数值 0/1**：

- 条件`e`成立 → 数值 `1`

- 条件`e`不成立 → 数值 `0`

- 取反等价式（核心化简恒等式）：
$!e = 1 - e$

### 2\.2 基础单分支转换模板

#### 模板 1：简单 if（无 else）

原始代码

```c
if(e) {
    // 分支内全部计算，最终赋值 x = Val_true
    x = Val_true;
}
// 无else，不执行时x保持原值
```

AF 转换公式：
$x = e \cdot Val_{true} + (1-e) \cdot x$

$x = e \cdot Val_{true} + (1-e) \cdot Val_{false}$

### 2\.4 嵌套 if\-else 递归转换规则（核心自动化逻辑）

嵌套分支遵循**由内向外递归处理**：

1. 找到最内层条件分支；

2. 将内层所有计算合并为单一表达式 $InnerExpr$；

3. 用 $InnerExpr$ 替换外层分支对应的赋值结果；

4. 对外层条件重新套用 if\-else 转换公式；

5. 多层嵌套循环递归直至无内层分支。

示例嵌套结构：

```c
if(e1) {
    if(e2) { x = p; } else { x = q; }
} else {
    x = r;
}
```

步骤 1：扁平化内层 e2
$Inner = e2\cdot p + (1-e2)\cdot q$
步骤 2：代入外层 e1
$x = e1 \cdot Inner + (1-e1) \cdot r$
展开完整式：
$x = e1 \cdot \big[e2\cdot p + (1-e2)\cdot q\big] + (1-e1)\cdot r$

### 2\.5 else if 多分支链通用求和公式（论文通用 α 公式）

多分支 else if 链统一使用**乘积求和范式**，所有分支互斥（同一时刻仅一条条件为 1）：
$\alpha = \sum_{i=0}^{n} Cond_i \cdot Val_i$

- $Cond_i$：第 i 条分支的互斥布尔条件

- $Val_i$：第 i 条分支内全部计算合并后的最终赋值表达式

- 全部分支求和，直接替代整条 else if 控制流

论文标准示例 else if 链：

```c

else if(n==1) x=a+1;

else x=0;
```

### 2\.6 分支内含多步计算 / 临时变量处理规则

自动化预处理步骤（转换前必须执行）：

1. 遍历单分支内所有代码行；

2. 消除临时变量：将临时变量表达式原地替换到最终赋值；

3. 合并所有算术运算为单一 $Val_i$ 表达式；

4. 无额外改动，直接代入求和公式。

示例：分支内带中间计算


## 3 AF 自动化完整流水线（AI 可逐步骤复现）

### 阶段 1：代码预处理输入

输入：带分支的 GPU 内核代码片段
输出：标准化抽象语法树 AST

1. 词法语法解析，构建 AST；

2. 筛选所有控制流节点：if /if\-else/else if / 嵌套条件；

3. 划分独立代码块，分离循环、函数调用（跳过不处理）；

4. 提取每个分支内的所有赋值、算术计算，标记输出变量。

### 阶段 2：内层优先递归分支扁平化（核心转换）

循环执行直到 AST 无任何分支节点：

1. 检索当前 AST**深度最大的内层条件分支**；

2. 提取该分支 True 路径、False 路径内全部运算；

3. 消除路径内临时变量，合并为单表达式 $Val_{true},Val_{false}$；

4. 使用基础 if\-else 公式生成无分支算术表达式；

5. 用新算术表达式替换原 if 分支 AST 节点；

6. 重新生成简化后的 AST，回到步骤 1 循环。

### 阶段 3：代数表达式化简优化

对每一条生成的求和表达式依次执行化简：

1. 套用 $e\cdot a + (1-e)\cdot b = e(a-b)+b$ 压缩项；

2. 识别 `1-e` 统一替换为 `!e` 布尔简写；

3. 分支重排序优化：对比原表达式与反转条件表达式，选择运算量更少的形式；

4. 消除乘 0、冗余自加自减等无效运算；

5. 合并常数项、同类算术项。

### 阶段 4：多分支链标准化处理

针对 else if 互斥分支链：

1. 提取每条分支互斥条件 $Cond_0,Cond_1...Cond_n$；

2. 每条分支内部计算合并为 $Val_i$；

3. 按求和公式 $\sum Cond_i \cdot Val_i$ 拼接完整表达式；

4. else 分支赋值为 0 时直接删除对应项。

### 阶段 5：代码生成输出

1. 将化简后的纯算术表达式替换原有整块分支代码；

2. 移除全部 if/else/else if 关键字；

3. 保留原变量、算术运算，输出无分支 GPU 代码；

4. 输出统计信息：指令增量$R_I$、理论耗时占比$Exec_{AF}$。

### 阶段 6：性能预估校验（可选自动化模块）

使用论文性能模型做量化评估：

1. 统计原始分支代码 ALU 指令数 $I_{BR}$；

2. 统计 AF 扁平化后 ALU 指令数 $I_{AF}$；

3. 计算指令比：$R_I = \frac{I_{AF}}{I_{BR}}$

4. 采集 GPU 硬件利用率 $U_{BR}$（原始）、$U_{AF}$（AF 无分支）；

5. 耗时占比：$Exec_{AF} = R_I \times R_U,\quad R_U=\frac{U_{BR}}{U_{AF}}$

6. 理论加速比：$Speedup = \frac{1}{Exec_{AF}}$
